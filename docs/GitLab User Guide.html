GitLab Cliq Notifier - Customer Setup Guide

This guide helps your team enable Zoho Cliq notifications from GitLab pipelines in under 10 minutes.

Reusable include template
Supports user and bot mode
Optional AI merge request review

1) Add Include to Your Repository

Add this in your repository root .gitlab-ci.yml:

include:
  - project: 'your-group/gitlab-cliq-notifier'
    ref: main
    file: 'templates/cliq-notify.yml'

Replace your-group/gitlab-cliq-notifier with your actual GitLab path.

2) Configure CI/CD Variables

Important: these settings are already defined in the shared template YAML under variables:.

You can keep template defaults, or override any value per repository using GitLab CI/CD Variables.

Minimum required variables for current defaults: AI_REVIEW_TOKEN, ENDPOINT, GITLAB_TOKEN.

Go to Settings > CI/CD > Variables and add:

Variable Required Description
ENDPOINT Yes Zoho Cliq channel webhook URL including ?zapikey=<token>.
CUSTOM_MESSAGE No Custom message template. Leave as _+_ to use default auto message.
CLIQ_NOTIFICATION_MODE No user (default) or bot.
CLIQ_BOT_UNIQUE_NAME Only if bot mode Mandatory when CLIQ_NOTIFICATION_MODE=bot.
CLIQ_BOT_DISPLAY_NAME No Display name shown in Cliq for bot posts.
CLIQ_BOT_IMAGE_URL No Avatar URL shown in Cliq for bot posts.

3) Optional: Enable AI MR Review

If you want automated merge request review comments, set:

  • AI_REVIEW_ENABLED=true
  • AI_REVIEW_TOKEN (provider token or API key)
  • AI_REVIEW_SERVICE = openai, gemini, or claude (alias: anthropic)
  • AI_REVIEW_MODEL (exact model name)
  • AI_REVIEW_API_URL (provider endpoint URL)
  • GITLAB_TOKEN (with api scope for MR comments)

If any required AI variable is missing, the pipeline fails fast with a clear message.

Template defaults already include AI_REVIEW_SERVICE, AI_REVIEW_MODEL, and AI_REVIEW_API_URL. Update in YAML or override in CI/CD variables.

4) Events That Trigger Notifications

  • Push to default branch
  • Merge request event
  • Scheduled pipeline

If needed, your team can override the included job rules in your own .gitlab-ci.yml.

5) Custom Message Placeholders

Use these placeholders in CUSTOM_MESSAGE:

  • (me) - linked GitLab username
  • (repo) - linked project name
  • (event) - event label
  • (ref) - branch or tag link
  • (pull) - merge request title link
  • (sha) - short commit SHA
Example:
(me) pushed to (ref) in (repo) [commit: (sha)]

6) Validation Checklist

  • Pipeline runs without variable errors
  • Cliq message appears in target channel
  • Bot mode works (if configured)
  • AI MR review comment appears (if enabled)
