Zoho Cliq GitHub Informer

This document summarizes how the two repositories work together: one repository provides the reusable GitHub Action implementation, and the other provides the ready-to-use workflow template that consuming repositories can copy and configure.

Action Repo: GitHub-Informer-New Template Repo: TemplateRepositoryNew Features: Cliq notifications + Project thread reuse + AI review gate
Repository 1

GitHub-Informer-New

This is the reusable public GitHub Action. It contains the Java implementation that:

  • posts GitHub event notifications to Zoho Cliq,
  • supports user mode and bot mode,
  • stores and reuses Cliq thread IDs in GitHub Project V2,
  • runs the AI Review Gate and publishes a check run.
Open GitHub-Informer-New repository
Repository 2

TemplateRepositoryNew

This is the workflow template repo. It contains the ready-made .github/workflows/CliqConnector.yml file that consuming repositories can use directly.

  • wires secrets and variables into the action,
  • handles PR project pre-insert logic,
  • configures AI review inputs,
  • builds the final Cliq endpoint for user or bot mode.

Recommended Model

How Both Repositories Are Used

  1. Publish and version the action from GitHub-Informer-New using a tag such as v3.
  2. Keep the workflow template in TemplateRepositoryNew.
  3. In a consuming repository, copy CliqConnector.yml or use it as the reference workflow.
  4. Configure repository Secrets and Variables.
  5. The workflow calls Lincy-Zoho/GitHub-Informer-New@v3.
Best practice: users should not copy action source files locally. They only need the workflow file in their repo, while the action logic stays in the public action repo.
Setup

Required Secrets and Variables

Name Type Purpose
ENDPOINT Environment secret Cliq channel endpoint with ?zapikey=.... Must be created in the cliq-production environment unless the workflow environment name is changed.
AI_REVIEW_TOKEN Environment secret API token for the selected AI provider when AI review is enabled. Must also live in the cliq-production environment by default.
PROJECT_TOKEN Environment secret Classic GitHub PAT used for Project V2 operations. Required for thread storage mode and stored in the cliq-production environment.
CLIQ_THREAD_STORAGE_MODE Repository variable Set to project when thread reuse is enabled.
GITHUB_PROJECT_OWNER Repository variable GitHub org or user that owns the Project V2.
PROJECT_NUMBER Repository variable Required only for thread reply mode. GitHub Project V2 number used to resolve the PR item.
PROJECT_THREAD_FIELD_ID Repository variable Required only for thread reply mode. Custom Project field ID used to store the Cliq thread ID.
CLIQ_NOTIFICATION_MODE Repository variable Set to user or bot.
CLIQ_BOT_UNIQUE_NAME Repository variable Required only when mode is bot.
AI_REVIEW_ENABLED Repository variable Must be created before the workflow is triggered.
AI_REVIEW_SERVICE Repository variable Required for the AI review flow, for example openai, claude, or gemini.
AI_REVIEW_MODEL Repository variable Required for the AI review flow and must match the selected provider.
This workflow expects the environment secrets under the GitHub environment named cliq-production. If a different environment name is used, the workflow environment name must be changed in the YAML to match it. The values referenced as ${{ vars.* }} must be created in GitHub under Settings → Secrets and variables → Actions → Variables. Runtime values such as github.repository_owner, github.repository, and github.event.pull_request.number are read from GitHub automatically and should not be manually added by the user.
Workflow Placement

Where to add the workflow file

Create the workflow in your consuming repository at:

.github/workflows/CliqConnector.yml

If the .github/workflows folder does not exist, create it first. This is the path GitHub reads when it looks for workflow files.

The reusable action source code is in the public action repository here:

https://github.com/Lincy-Zoho/GitHub-Informer-New/blob/main/src/GitHub_Informer_New.java
Configuration Rules

Strict Setup Model

  1. Environment secrets: ENDPOINT, AI_REVIEW_TOKEN, and PROJECT_TOKEN. By default these are created in the GitHub environment named cliq-production.
  2. Automatic GitHub token: GITHUB_TOKEN is provided by GitHub runtime and does not need to be configured manually.
  3. Repository variables: use all app-level values such as CLIQ_NOTIFICATION_MODE, CLIQ_BOT_UNIQUE_NAME, CLIQ_THREAD_STORAGE_MODE, GITHUB_PROJECT_OWNER, PROJECT_NUMBER, PROJECT_THREAD_FIELD_ID, AI_REVIEW_ENABLED, AI_REVIEW_SERVICE, and AI_REVIEW_MODEL.
  4. Do not hardcode these values in the workflow YAML. Read them from repo variables or environment secrets instead.
Normal channel reply mode does not require the project number or thread field ID. Thread reply mode does require both. If the action is posting to a normal Cliq channel instead of reusing a thread, the GitHub Project settings are not needed. The repository variables for AI review are mandatory before the workflow is triggered.
First-Time Setup

Correct Order for a New Repository

  1. Add the required repo variables and secrets.
  2. Commit and push the workflow file.
  3. Run the workflow once so the status check is created in GitHub.
  4. Then add the branch protection or ruleset and require the AI Review Gate check.
This order matters because GitHub cannot enforce a required status check before that check has been created by the workflow. The required status check is configured in GitHub Rules / Branch Protection, not in the workflow YAML or repository variables.
Notification Modes

User Mode vs Bot Mode

Mode What User Sets Notes
User mode CLIQ_NOTIFICATION_MODE=user Uses the existing ENDPOINT secret as-is. No bot unique name is required.
Bot mode CLIQ_NOTIFICATION_MODE=bot
CLIQ_BOT_UNIQUE_NAME=<bot-name>		 The workflow reuses ENDPOINT and appends bot_unique_name automatically.

Two Supported Ways to Provide Mode Values

  1. GitHub Variables in repository settings.
  2. Direct values in CliqConnector.yml.
env:
  CLIQ_NOTIFICATION_MODE: ${{ vars.CLIQ_NOTIFICATION_MODE || 'user' }}
  CLIQ_BOT_UNIQUE_NAME: ${{ vars.CLIQ_BOT_UNIQUE_NAME || '' }}
Recommended approach: use GitHub Variables for CLIQ_NOTIFICATION_MODE and CLIQ_BOT_UNIQUE_NAME. For a normal channel reply, PROJECT_NUMBER and PROJECT_THREAD_FIELD_ID are not required. For a thread reply, both are required.
Bot Setup

How to Configure Bot Mode in Zoho Cliq

  1. Create the bot in Zoho Cliq.
  2. Open Integrations -> Bots.
  3. Select the bot you created.
  4. In the bot details panel, check the API Endpoint.
  5. The value after /bots/ is the bot unique name.
  6. Add the bot to the target Cliq channel.
Example API endpoint:
https://cliq.zoho.com/api/v2/bots/githubnotification/message

Bot unique name:
githubnotification
Project Reuse

How Cliq Thread Reuse Works

  1. The action resolves the PR item in GitHub Project V2.
  2. It reads the existing value from the configured custom field.
  3. If no thread id exists, it posts a new Cliq message.
  4. It extracts the returned message_id.
  5. It saves that id in the Project V2 custom field.
  6. Later PR events reuse the same thread.
AI Review

AI Review Gate Flow

  1. The workflow runs AI review on pull_request_target.
  2. The action fetches PR diff, sends it to the configured AI provider, and parses the result.
  3. It creates a GitHub check run using ai-review-check-name.
  4. If the AI result is PASS, merge can proceed.
  5. If the AI result is FAIL, the PR gets a comment and the Cliq PR thread receives the failure report.

Required Status Check Setup

  1. Set the workflow input ai-review-check-name to the desired check name.
  2. Run the workflow once on a PR.
  3. In GitHub Rules or Branch Protection, enable Require status checks to pass.
  4. Add the exact same check name as a required check.
Exact name matching matters. If the required check name and the workflow check name differ, GitHub shows Waiting for status to be reported.
Workflow Shape

High-Level Execution Flow

  1. Resolve mode and prepare Cliq endpoint.
  2. Validate Project V2 token.
  3. Ensure the PR exists in the GitHub Project.
  4. Post the notification to Cliq.
  5. Save or reuse the PR thread id.
  6. Run AI Review Gate and publish the status check.
Reusable Template

Project Template File

The reusable CI template lives in templates/cliq-notify.yml and is included from a consuming repo using the standard GitLab include pattern.

# .gitlab-ci.yml (in the consuming repository)
include:
  - project: 'your-group/gitlab-cliq-notifier'
    ref: main
    file: 'templates/cliq-notify.yml'
# templates/cliq-notify.yml
# Reusable GitLab CI template for Zoho Cliq notifications.
# Java source is fetched at runtime from GitHub-Informer-New (single source of truth).
#
# ── HOW TO USE IN A CONSUMING REPO ────────────────────────────────────────────
#
#   .gitlab-ci.yml (in your project repo):
#
#     include:
#       - project: 'your-group/gitlab-cliq-notifier'
#         ref: main
#         file: 'templates/cliq-notify.yml'
#
#   Then set these CI/CD Variables in Settings → CI/CD → Variables:
#
#   Required:
#     ENDPOINT               Cliq channel URL + ?zapikey=<token>
#
#   Optional:
#     CLIQ_NOTIFICATION_MODE  user (default) or bot
#     CLIQ_BOT_UNIQUE_NAME    Required when mode is bot
#     CUSTOM_MESSAGE          Custom message text, or _+_ for auto-generated
#     AI_REVIEW_TOKEN         API token/key for the chosen AI_REVIEW_SERVICE — OpenAI key,
#                               Gemini API key, or Anthropic key (required if AI_REVIEW_ENABLED=true)
#     AI_REVIEW_ENABLED       true to enable AI MR review gate
#     AI_REVIEW_SERVICE       REQUIRED if AI_REVIEW_ENABLED=true. No default — must be filled in.
#     AI_REVIEW_MODEL         REQUIRED if AI_REVIEW_ENABLED=true. No default — must be filled in.
#     AI_REVIEW_API_URL       REQUIRED if AI_REVIEW_ENABLED=true. No default — must be filled in.
#     GITLAB_TOKEN            Project/Personal Access Token with 'api' scope (for MR comments)
#
stages:
  - notify

cliq-notify:
  stage: notify
  image: eclipse-temurin:19-jdk

  rules:
    - if: '$CI_PIPELINE_SOURCE == "push" && $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH'
    - if: '$CI_PIPELINE_SOURCE == "merge_request_event"'
    - if: '$CI_PIPELINE_SOURCE == "schedule"'

  variables:
    CUSTOM_MESSAGE: "_+_"
    CLIQ_NOTIFICATION_MODE: "user"
    CLIQ_BOT_UNIQUE_NAME: ""
    CLIQ_BOT_DISPLAY_NAME: "GitLab Informer for Zoho Cliq"
    CLIQ_BOT_IMAGE_URL: "https://workdrive.zohoexternal.com/external/a55ce4b1d1b64d36de31b77b6067d0a74b47b8733459390605c849bc880b05e8/download?directDownload=true"
    CLIQ_INFORMER_REF: "main"
    CLIQ_JAVA_SOURCE_REPO: "cliq-gitlab-informer/gitlab-cliq-java-source"
    AI_REVIEW_ENABLED: "true"
    AI_REVIEW_SERVICE: "gemini"
    AI_REVIEW_MODEL: "gemini-2.0-flash"
    AI_REVIEW_API_URL: "https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-flash:generateContent"

  before_script:
    - apt-get update -qq && apt-get install -y -qq git
    - git clone --depth 1 --branch "$CLIQ_INFORMER_REF"
        https://gitlab.com/${CLIQ_JAVA_SOURCE_REPO}.git /tmp/cliq-informer
    - mkdir -p /tmp/cliq-informer/out
    - javac /tmp/cliq-informer/src/GitLab_Cliq_Informer.java -d /tmp/cliq-informer/out

    - |
      if [[ "$(echo "${AI_REVIEW_ENABLED:-false}" | tr '[:upper:]' '[:lower:]')" == "true" ]]; then
        missing=()
        [[ -z "$AI_REVIEW_TOKEN" ]]     && missing+=("AI_REVIEW_TOKEN")
        [[ -z "$AI_REVIEW_SERVICE" ]]   && missing+=("AI_REVIEW_SERVICE")
        [[ -z "$AI_REVIEW_MODEL" ]]     && missing+=("AI_REVIEW_MODEL")
        [[ -z "$AI_REVIEW_API_URL" ]]   && missing+=("AI_REVIEW_API_URL")
        if [[ ${#missing[@]} -gt 0 ]]; then
          echo "ERROR: AI_REVIEW_ENABLED=true but the following required CI/CD variables are not set:"
          for m in "${missing[@]}"; do echo "  - $m"; done
          exit 1
        fi

        service_lc=$(echo "$AI_REVIEW_SERVICE" | tr '[:upper:]' '[:lower:]' | xargs)
        case "$service_lc" in
          openai|gemini|claude|anthropic)
            ;;
          *)
            echo "ERROR: AI_REVIEW_SERVICE=\"$AI_REVIEW_SERVICE\" is not a supported value."
            exit 1
            ;;
        esac
      fi

    - |
      if [[ -z "$ENDPOINT" ]]; then
        echo "ERROR: ENDPOINT CI/CD variable is not set."
        exit 1
      fi
      mode=$(echo "${CLIQ_NOTIFICATION_MODE:-user}" | tr '[:upper:]' '[:lower:]')
      if [[ "$mode" == "bot" ]]; then
        if [[ -z "$CLIQ_BOT_UNIQUE_NAME" ]]; then
          echo "ERROR: CLIQ_BOT_UNIQUE_NAME is required when CLIQ_NOTIFICATION_MODE=bot."
          exit 1
        fi
        if [[ "$ENDPOINT" == *"?"* ]]; then
          export RESOLVED_ENDPOINT="$ENDPOINT&bot_unique_name=$CLIQ_BOT_UNIQUE_NAME"
        else
          export RESOLVED_ENDPOINT="$ENDPOINT?bot_unique_name=$CLIQ_BOT_UNIQUE_NAME"
        fi
      else
        export RESOLVED_ENDPOINT="$ENDPOINT"
      fi

  script:
    - java -cp /tmp/cliq-informer/out GitLab_Cliq_Informer "$RESOLVED_ENDPOINT"
This pattern keeps the reusable logic in one template file, while each consuming project only needs to include it and define the required CI/CD variables such as ENDPOINT and AI_REVIEW_TOKEN.
